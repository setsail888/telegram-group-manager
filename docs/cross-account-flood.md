# 跨账号防刷屏与惩罚

## 从哪里开启

私聊机器人 `/start` → 选择群组 → **防刷屏 → 跨账号重复**。

1. 保持防刷屏主开关开启，选择「仅观察」，预览后确认。
2. 查看「防护记录」，按群内正常讨论调整人数、条数、窗口和最短文字。
3. 确认规则适合本群后，选择「自动清理」并确认；「智能反垃圾 → 仅观察内容过滤」必须关闭，才会实际清理。
4. 在「防刷屏 → 惩罚」选择当前触发者的处理方式，预览后确认。

设置持续保存在本群数据库。**十分钟只限制本次预览确认**，不是功能只能开启十分钟。确认会重新检查本人、群组、原预览消息、管理权限和设置快照；过期、重复确认或其他管理员已改动设置时，需要重新预览。升级代码后，原群配置继续保留，跨账号检测默认关闭。

## 怎么判断同内容刷屏

| 参数 | 初始值 | 可调范围 |
| --- | --- | --- |
| 模式 | 关闭 | 关闭 / 仅观察 / 自动清理 |
| 相同消息数 | 5条 | 3–30条 |
| 不同账号数 | 3人 | 2–30人 |
| 时间窗口 | 60秒 | 5–300秒 |
| 文字最短长度 | 8个非空白字符 | 2–200个字符 |

在**同一群、同一话题、同一滚动窗口**内，消息数和不同账号数必须同时达标。例如三个账号依次发送同一段推广文案，累计到第五条时触发；一个账号发五条仍由原来的个人刷屏规则处理。普通「谢谢」「收到」等短回复默认不参与跨账号检测，调低最短长度会增加多人正常互动被清理的可能。

### 按初始参数看几个例子

以下均假设防刷屏开启、本项为自动清理、全局观察关闭，消息内容相同且满足最短长度：

| 60秒内的发送情况 | 本项是否触发 |
| --- | --- |
| A发2条、B发2条 | 不触发：总数4条、账号2人，都未达标 |
| A发3条、B发2条 | 不触发：达到5条，但仍只有2人 |
| A、B、C各发1条 | 不触发：达到3人，但只有3条 |
| A发2条、B发2条、C发第5条 | 触发：同时达到5条和3人；清理缓存中的同内容消息，只处罚当前触发的C |
| 5条相同消息分布在两个话题里，每个话题都未达标 | 不合并计数 |

这些“不触发”只表示没有触发跨账号规则，独立的个人刷屏、违禁词或链接规则仍可能处理。

比较完整正文或媒体说明、媒体的Telegram稳定标识、按钮文字/链接及隐藏链接目标；统一大小写、全半角和零宽字符。前半段相同、后半段不同的长消息不会仅凭开头被合并。不同图片、不同隐藏链接会分开；空格和标点变化仍会区分，不进行任意谐音或语义相似合并。相同媒体不要求说明达到最短字数，也受本规则控制。

多人同时发送 `/checkin`、`/joinraffle` 等本项目已知的无参数成员命令不参与跨账号检测，避免签到/报名误报；带参数、媒体、按钮或隐藏目标仍参与检查。同一账号频繁发送命令，原有个人防刷屏继续生效。关闭本项或仅观察，不会关闭独立的违禁词、链接、媒体等防护。

## 命中后会清理什么

触发消息先走单条删除。确认成功后，批量清理窗口内缓存的同内容消息；**只对当前触发者执行成员处罚，早先作者只撤回，不追罚**。这样可以降低有人复制正常成员消息、反过来处罚原作者的风险。已确认的同内容刷屏在持续发送期间继续拦截，安静一个完整窗口后解除。

管理员、机器人及本群匿名管理员豁免；清理前重新核验身份，早先作者已升为管理员时跳过。无法取得可靠身份时跳过相应处理。编辑消息会移出旧候选，不增加跨账号次数，也不追加成员处罚。已经被其他文字规则或OCR成功删除的消息会标记处理，避免再次提交批量清理。

机器人只处理自己实际收到并缓存的消息，不读取群历史、不扫描整个群。每种内容最多缓存100条，全局最多20,000条、5,000种内容，计数/摘要最长保留300秒；每次判断仍按本群的窗口裁剪。改变检测参数/模式或机器人重启后，重新累计。只保存内容摘要、消息ID、作者ID等元数据，不保存原文或图片。清理无法撤销此前已经完成的签到、兑换、报名等业务操作。

仅观察时记录命中，不删消息、不追加处罚，也不加入累计违规历史。全局观察优先；本项观察不会放过其他可执行的独立违规规则。

## 五种惩罚怎么选

入口：**防刷屏 → 惩罚**。这些选项适用于短时刷屏、个人重复刷屏、媒体刷屏及跨账号重复刷屏；违禁词和链接仍用各自规则。

| 选择 | 触发消息删除成功后的操作 |
| --- | --- |
| 仅撤回消息，不处罚 | 不追加成员处罚，本次刷屏也不计入全局累计违规禁言 |
| 警告 | 累加本群警告次数；与管理员手动警告共用计数，达到上限后尝试按防刷屏禁言时长禁言，成功才清零，失败保留警告 |
| 禁言 | 按配置时长限制当前发送者 |
| 踢出 | 移出当前发送者，允许重新加入 |
| 踢出＋封禁 | 移出并阻止重新加入，直到到期或管理员解封；可选永久 |

成员处罚需要超级群、机器人删除消息与限制成员权限，执行前重新核验目标为在群普通成员。删除失败不追加成员处罚；处罚失败单独记录，不自动升级为永久封禁或转用其他更重处罚。警告记录和处罚成功通过现有管理日志输出，默认不在群内额外公开通知。删除提醒仍可独立设置。

禁言/封禁可点击10分钟、1小时、1天、7天、30天、365天预设，或输入**1–525600分钟**；封禁的**0分钟为永久**。Telegram把少于30秒或超过366天的限制视为永久，因此界面将有限时长限制在365天以内，见官方[禁言接口](https://core.telegram.org/bots/api#restrictchatmember)与[封禁接口](https://core.telegram.org/bots/api#banchatmember)。时长只影响今后的处罚，不会改写已有成员限制。

**超级群封禁会撤销该成员的其他历史消息**，这是Telegram封禁接口的行为，选择封禁时预览会提示。踢出使用[移出且允许重进的接口语义](https://core.telegram.org/bots/api#unbanchatmember)，不先施加永久封禁。希望只清理检测到的消息时，可选择仅撤回、警告、禁言或踢出。

旧版「单次仅删除触发消息」继续兼容已有全局累计规则，面板会提示；新版「仅撤回消息，不处罚」明确退出本次刷屏的全局累计禁言。其他四种明确处罚也不与全局累计禁言叠加。独立的违禁词、链接违规仍可按各自规则处罚。

## 记录怎么看

「防护记录」区分单条「已删除」、批量「清理已提交」、失败和观察，并显示当前触发者的处罚方式及执行结果。Telegram的[批量删除接口](https://core.telegram.org/bots/api#deletemessages)会跳过不存在的消息ID，返回成功不能证明每一条实际删除，因此批量请求数量单独统计，不冒充逐条确认删除数量。批量失败时保留待处理候选，后续相同内容再次触发会重试；没有后台重试队列。

成员处罚使用数据库中的群组/消息唯一记录防止重复投递或重启后再次处罚，记录保留30天、每群最多10,000条。已占用的处罚请求失败后不通过重放自动补罚；可查看记录后由管理员手动处理。批量历史清理不生成早先作者的警告、禁言或累计违规次数。

部署更新后，先用测试群的普通成员账号核验清理范围、处罚对象和权限，再按本群消息样本选择阈值。文字测试只能检查文字规则，不能模拟多个账号的累计过程。
