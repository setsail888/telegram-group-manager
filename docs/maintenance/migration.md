# 服务器迁移：从A搬到B

继续使用同一个Telegram机器人，将A上的群设置、词库、积分和订单搬到B。无需重新创建Bot，也不需要把机器人退出群再加入。

**入口：服务器SSH中执行 `gg` → 8 服务器迁移。** 也可直接使用 `gg migrate export` 和 `gg migrate import`。

迁移顺序：**A更新 → A导出并停止 → 安全传输迁移包 → B准备环境 → B导入并启动 → 核对数据。**

## 会迁移哪些内容

| 内容 | 处理方式 |
| --- | --- |
| 群配置、违禁词、词库开关、例外、匹配方式 | 保留数据库内全部设置与规则 |
| 积分、签到、商城商品、订单、抽奖及报名 | 完整保留；不是将两个机器人的数据合并 |
| 自动回复、欢迎语、群规、定时公告、统计及防护记录 | 按当前保存的数据迁移 |
| 个人界面语言、群内提示语言、更新处理进度 | 保留数据库记录 |
| Bot Token、管理员ID、时区、OCR及其他运行配置 | 随迁移包加密保存，导入后沿用 |
| Docker数据卷中的其他普通文件 | 一并导出、校验并导入 |
| 网页看板 | 保留配置和密钥，B不会自动启动看板；需要时执行 `gg dashboard` |

未提交的编辑草稿、确认按钮、短时刷屏计数等内存状态会随重启失效。Telegram媒体以原Bot的文件标识保存，继续使用原Bot Token。

迁移不包含服务器上的其他网站、SSH密钥、证书、代理服务和手工修改的源码。B使用安装目录中的代码；自定义外部API、代理或文件路径，需确认B也能访问对应资源。本功能面向本项目的标准Docker部署，数据库需位于 `/app/data/` 下。

## 1. A服务器更新并导出

在A的SSH终端执行：

```bash
gg update
gg migrate export ~/groupguard-migration.ggm
```

输入迁移包密码两次，至少12个字符，输入时不显示。保存好密码，B导入时需要相同密码；程序不保存密码，也不能找回。

导出会停止机器人和正在运行的看板，复制数据卷，再用SQLite快照纳入已提交的WAL数据。成功后显示数据概览及迁移包路径，**A保持停止，原配置和原数据保留**。导出失败时尝试恢复A原来的运行状态。

重复导出请换一个文件名，程序不会覆盖旧包。省略路径时，自动在 `~/groupguard-backups` 生成带时间和随机标记的新文件：

```bash
gg migrate export
```

主菜单8 → 1也执行相同操作。

## 2. 把迁移包传到B

例如在A执行，替换B的用户名和地址：

```bash
scp ~/groupguard-migration.ggm 用户@B服务器IP:~/
```

也可通过自己的SFTP客户端下载后上传。迁移包包含Bot Token及群数据，虽然已加密，仍应妥善保管；密码通过独立方式保存，不写进命令、文件名或公开聊天。

**传输期间不要重新启动A。** 如果A在导出后又运行过，新的积分、订单等变化不在旧包中，需要重新停止并导出。

## 3. B服务器只准备环境

在B的SSH终端执行：

```bash
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/slobys/telegram-group-manager/main/install.sh | bash -s -- prepare'
```

这会下载代码、检查或安装Docker、准备Python标准运行时和OpenSSL，并注册 `gg` / `GG`。**不会要求输入新Token，也不会启动机器人。** 不要先按普通安装流程启动一个空数据库的机器人。

已有源码时可直接执行：

```bash
bash ~/groupguard/install.sh prepare
```

自定义安装目录请替换路径。Python和OpenSSL仅用于服务器迁移，机器人本身没有新增Python依赖。

## 4. B导入并启动

```bash
gg migrate import ~/groupguard-migration.ggm
```

输入迁移密码。工具先校验加密包、文件清单、文件内容和SQLite完整性，再显示机器人ID与群组、规则、积分账户、订单等数量；不会显示Token。

确认A已停止、目标确实是B后，输入 **MIGRATE**。主菜单8 → 2也可按提示输入文件路径。

导入会：

1. 停止B现有机器人和看板。
2. B已有数据时，先生成 `groupguard-before-import-*.ggm` 加密备份，使用本次迁移密码；备份失败则不覆盖。
3. 沿用A的运行配置构建B镜像，替换本项目的数据卷内容，并逐文件复核。
4. 校验成功后启动B机器人。

如果A启用了OCR，B会按迁入的配置构建带OCR的镜像，可能需要更多时间和磁盘空间。B源码早于迁移包时会拒绝导入，先在安装目录运行 `git pull --ff-only origin main` 更新代码，再导入。

B历史数据缺少原`.env`时会停止操作，避免无法备份和恢复旧配置。不要为了绕过检查删除数据卷。

## 5. 核对迁移结果

在B执行：

```bash
gg status
gg logs
```

确认日志能够正常连接Telegram；私聊机器人重新发送 `/start`，核对群列表、规则开关、关键词、积分余额、订单和定时公告。OCR用户同时查看引擎状态。

容器启动成功不等于Telegram网络已经验证成功。确认B稳定后再处理A；建议保留A及加密迁移包一段时间。**同一个Bot只保留一台服务器运行**，避免长轮询冲突和数据分叉。

## 失败和恢复

| 情况 | 处理 |
| --- | --- |
| 密码错误、包被修改或数据库损坏 | 校验阶段拒绝导入，B原配置和数据不变；检查密码或重新传包 |
| B磁盘不足、构建失败或复制校验失败 | 工具尝试恢复B原配置、数据和原运行状态；查看明确的恢复结果 |
| B自动恢复未完成 | 先排查Docker、权限与磁盘问题，保持机器人停止，保留 `before-import` 加密备份 |
| 决定取消迁移，继续使用A | 先确认B已停止，再在A执行 `gg service` → 选择启动 |

需要使用B导入前的完整备份恢复时，修好底层问题后执行：

```bash
gg migrate import ~/groupguard-backups/groupguard-before-import-实际文件名.ggm
```

使用该次迁移的密码，核对机器人ID和数据概览后确认。自动回滚只恢复本地配置和数据，不能撤销已经发生的Telegram操作；失败后先检查日志，再决定恢复哪台服务器。

`gg backup`生成的旧`.sqlite3`文件只包含数据库，不能当作`.ggm`迁移包导入。两台服务器无需开放新的业务端口，文件传输使用已有SSH/SFTP。

## 加密与校验

迁移包使用OpenSSL AES-256-CBC与PBKDF2加密，另用独立派生的HMAC-SHA256密钥验证包头和完整密文，校验通过后才解密。密码通过标准输入交给OpenSSL，不放在命令参数或环境变量里。加密文件权限600，临时解密数据保存在权限700的私有目录并在任务结束后清理。

导入仅允许清单中的普通文件，不接受路径穿越、符号链接、硬链接或重复条目；文件SHA-256和数据库完整性都需通过。[OpenSSL参数说明](https://docs.openssl.org/3.0/man1/openssl-enc/)。
