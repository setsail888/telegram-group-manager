# 统计、排行与管理日志

## 今日、近7天和活跃排行

管理菜单可打开 **今日统计、最近7天、活跃排行**。群内命令分别为 `/stats`、`/statweek`、`/top7`，默认由管理员查询。

活跃排行统计未被拦截的普通文字或说明消息，只保存日期、用户ID和消息数，不保存消息正文。不是全部历史消息统计，也不是独立访客数。

**规则总览** 可查看当前群开关与参数，适合确认更新后是否仍沿用原设置。不同群数据分别保存。

## 防护记录

**入口：防护记录，或智能反垃圾 → 查看防护记录。** 可按页查看命中原因、消息/成员ID、词条/分类、识别类型和执行结果，并标记已复核。

| 结果 | 如何理解 |
| --- | --- |
| 观察 | 规则命中，只记录，没有执行该项处罚 |
| 已删除 | 单条删除接口执行成功 |
| 批量清理已提交 | Telegram接受批量请求，不代表每个消息ID都已逐条确认删除 |
| 失败 | 删除或处理失败，查看权限和网络 |
| 成员处罚结果 | 警告、禁言等是否执行，和消息删除结果分开记录 |

记录保留30天、每群最多1000条，只存元数据。已删除消息无法从记录恢复；打开原消息需要群访问权限。标记已复核只是管理标记，不会自动修改规则。

发现误判后，应调整[词条例外](../moderation/import-export.md#精确例外怎么用)、[白名单](../moderation/anti-spam.md#域名白名单)或阈值，再测试。

## 独立管理日志群

1. 创建私人日志群或频道，将机器人加入并设为管理员。
2. 管理员本人也必须具备目标群相应管理身份。
3. 在目标群发送 `/id` 获取负数ID。
4. 回到原群的 **管理日志 → 设置/关闭日志群**，输入ID并确认；输入0关闭。

群内也可使用 `/setlog -100实际日志群ID`，关闭用 `/setlog off`。不要把原群本身设为日志目标，以免向所有成员公开管理记录。

日志群需要机器人发消息权限。OCR仅审核和管理处罚等信息可输出到该群，实际消息是否发送还取决于功能模式和网络。
